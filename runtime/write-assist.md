# 编写辅助

包内路径相对本文件解析；读取目标项目材料时仍使用项目路径。

## 开始编写前

1. 确认已完整读取[共同约束](../docs/modules/constraints-common.md)、[准备入口](prepare.md)和所选完整[类型模板](../templates/_index.md)；首次生成文稿、实际骨架文字或建议前完整读取[编写规则 G1/G3](../docs/modules/constraints-writing.md)及本文件，不能只根据摘要或 H1–H9 推断原文。
2. 本文件后半保留 Phase 3、5.2.2 与 5.8.1/5.8.4/5.8.7 的完整常规原文，必须读完。实际提出技术架构决策前完整读[D1](../docs/modules/constraints-architecture.md)，再按当前类型与变体应用。
3. 使用额外示例前读[示例指导](../docs/modules/5.2-examples.md)，核对[来源状态](../examples/SOURCES.md)的对应记录，再读所选完整片段，不批量加载。未核验草稿不作正向 few-shot；短样本不替代完整模板，示例不是目标项目事实。
4. 按模板读取当前设计分支；程序详细设计（含无代码示例）、新代码或改编示例读[代码规范](../templates/tech-design/code-conventions.md)。人工／模型评审、自定义判定器或判定异常涉及测试结论时，读[测试证据指导](../docs/modules/test-evidence-presentation.md) §4，正常返回也适用。
5. 使用表格前读[表格规范](../docs/modules/5.8-tables.md)，代码、配置、命令或文件树代码块前读[代码块规范](../docs/modules/5.8-code-blocks.md)。涉及结构或流程关系、需要判断是否用图时先读[Mermaid 规范](../docs/modules/5.8-mermaid.md)，不能先决定不画图绕过原触发条件。

## 按信息选择表达方式

按所选变体保留类型分工、锚定节、必需字段与固定格式；非固定顺序、表达及自定义模块按读者任务调整。项目正文按 C5 写项目本身，不以本轮修改或验证记录代替。按 5.8 组织真实关系，保留必要短段论证，不连续多段纯散文或逐段套列表、表格；删重复，不删事实、原因、依据和限制；无法确认时重读模板。

Quickstart 按准备阶段确定的读者任务组织：

- 首屏给真实主要功能的必要输入、最小可复制操作与结果确认；确认用户所得成果，不把作者的规则核对或检查记录审阅列为普通使用者的必做步骤。必要执行状态由作者另行说明，必要参数、环境、权限和保存条件不能省略。
- 自然语言接口先示范用户材料到目标产物，例如“根据我提供的材料，写一份操作指南”（仅为调用形式示意）。实际入口与必要输入按项目确定，不默认给内部工具写说明；默认行为、模板选型和内建检查由助手承担，不转交用户。用户定制与必要澄清保留，不预设长提示词或字数上限。
- 与当前任务无关的实现、进阶配置、扫描及手工验收细节后置，辅助依赖不阻断本可用的主要功能。用户明确要求扫描器等工具的指南时，按指定任务写；手动调用与写入授权仍须明确。

架构需解释组成、职责、边界与依赖时按 5.8.2 画 Mermaid 结构关系图，目录树或步骤图不能替代；一句可说清的简单关系不硬画，非架构不强制有图。按真实项目画模型与资源关系，交付前渲染并核对图是否回答本节问题；未能渲染如实说明。代码、配置、命令核对版本与环境，引用保留原貌。

## 写作中的检查

- 每节先明确结论或要点，再给支撑信息。参考文档不追加主观决策；纪要不替参与者新增理由或排序。
- 对数字和关键判断执行 G2：区分实测、估算、待验证以及事实、假设、判断。目标和契约值说明性质即可，版本号、状态码、日期、编号不逐一加实测标记。
- 每节完成后检查 G1、C6 与内容密度：用常用语言写对象、行为、条件与结果，不直接抛内部术语；必要术语、前置条件、鉴权契约和安全警告保留，不因重复次数删除。
- 义务、证据和状态按 5.8.7 直接陈述；删无新增信息的自辩、预防性解释及 G1 转折否定铺垫，不为保留补解释；必要限制就地说明，不重复免责。不强制标签或装饰符号，技术语法与真实引用保留。

## 初稿完成后

进入[验证入口](verify-checks.md)。编写时已经注意某条约束，不代表收尾时可以省略检查；事实缺口不靠润色变成已知事实。

## 本阶段原文

#### Phase 3: 编写

主 agent 按文档骨架逐节编写，编写过程中同时执行约束体系（C1-C6, G1-G3）。

**编写顺序**：

1. 核心决策/结论章节先写——倒逼先形成判断，避免先写铺垫后补结论
2. 支撑论证章节其次
3. 范围声明和摘要最后写——基于已完成的正文，避免先写摘要后凑内容

**编写粒度**：

- 逐节编写，每节完成后执行该节的局部检查（G1 禁用扫描 + C6 术语检查）
- 长文逐节检查；减少后段遗漏是设计假设，尚无遵守率实测

**Subagent 委托条件**（仅在以下情况委托，详见 5.7）：

- Best-of-N 竞选
- 章节间无强依赖且主 agent 上下文已满

**输出**：文档全文初稿

#### 5.2.2 排版类型（跨文类一等公民）

先按内容选择排版，再填章节；具体表达沿用 5.8。

| 排版类型 | 形态 | 适用场景 |
|---------|------|---------|
| 倒金字塔 | 第一段就能办事，细节递进往后 | PRD 目标、Changelog、会议决议 |
| 问题→方案→代价 | 问题、选择和代价相连；必要短段配合真实分类、对照或图 | 技术设计、ADR |
| 有序步骤 + 验证信号 | 编号命令，每步写"你应看到" | Tutorial、How-to、Runbook、测试步骤 |
| 定义列表 / 键卡片 | Name / Type / Default / Effect | 配置参考、API 字段、环境变量 |
| 契约表 | 输入、输出、错误码、约束 | API 端点、验收标准 |
| 时间线 | `HH:MM` 动作 → 结果 | 测试报告、事故复盘、会议纪要 |
| 差异对照 | Before / After 或 旧 / 新 | Changelog 迁移指南、非目标说明 |
| 决策日志 | 状态标记 + 一篇一事 | ADR |
| 索引 + 深链 | 目录只指路，正文不重复 | 文档集门户、API 概览 |

明确固定的格式须保留（如契约表字段）；其余按信息关系选择，不把排版建议锁为全文格式或固定顺序。

#### 5.8.1 表达形式选择矩阵

根据信息类型选择最合适的表达形式：

| 信息类型 | 推荐形式 | 不推荐形式 | 判断依据 |
|---------|---------|-----------|---------|
| 多选项并列比较（≥2 维度） | 表格 | 散文逐条描述 | 表格让维度对齐可比，散文需要读者自己对齐 |
| 有依赖的动作 | 编号步骤或阶段 | 连续散文 | 命令、条件、验证与失败处理放在对应步骤内 |
| 并列要求/特征/职责/故障/阅读入口 | 分组条目 | 连续散文 | 分类编号用于定位，不表示执行顺序 |
| 分支流程/场景交互 | flowchart / sequence | 连续散文 | 前者展示分支，后者展示一次场景的交互顺序 |
| 状态转换 | Mermaid state diagram | 表格 | 状态机的转换条件用图比表格清晰 |
| 数据模型/实体关系 | Mermaid ER diagram | 散文 | 实体间的关系用图一目了然 |
| 时间线/里程碑 | Mermaid gantt / timeline | 散文列表 | 时间维度用图比文字直观 |
| 系统边界/组件职责与依赖 | Mermaid 结构关系图，可用基础 flowchart 表达 C4 视图 | 仅列目录树、步骤图或混画层次 | 架构说明须回答组成、职责、边界与依赖；简单关系可一句说清时不硬画，不强制 C4 四层，容器不等于 Docker 容器 |
| 静态调用关系 | 调用图 | 写成必经执行路径 | 表示函数可能调用谁，不代表每次都会调用 |
| 设计中的调用顺序／嵌套 | 场景时序图或拟议调用树 | 标成真实调用栈 | 标明设计场景、条件和异步边界 |
| 故障中的嵌套调用 | 真实调用栈 | 用源码推演冒充现场 | 对应实际故障记录 |
| 目录/文件净变化 | 等宽文件树 | 大段路径叙述 | 注明范围、比较版本、增删改与重命名；删除标记不表示已删本地文件 |
| 单一概念的解释 | 必要短段，分类与关系按需结构化 | 连续多段纯散文、逐段套列表 | 保留上下文，分类必须有真实依据 |
| 因果论证/取舍分析 | 短段论证，按关系配比较表或图 | 连续多段纯散文、用图表替代理由 | 前提、推理与结论相连，图表展示关系或差异 |
| 映射/参数/契约 | 表格或条目 | 长段落 | 按固定字段查询 |
| 单个关键数字或结论 | 加粗内联 | 独立表格 | 一个数字不需要表格包裹 |

按实际依赖拆动作，不按动词数量拆句；保留对应步骤的权限、备份、等待和失败停止条件。

#### 5.8.4 标题层级与编号规范

**层级规则**：

- 最多使用 4 级标题（H1-H4）。超过 4 级说明文档结构需要重新组织
- 子标题不能自解释时（如"3.2 其他"），标题后加一句引导文字再接子标题。子标题已足够清晰时不强制加引导句
- 标题遵循 C1 的信息密度要求——必须准确描述该章节内容，不空泛

**编号规则**：

- 顶层章节使用数字编号（1. 2. 3.）
- 子章节使用层级编号（1.1 1.2 2.1）
- 列表项内部再嵌套时使用字母（a. b. c.）或无序列表，不再使用数字（避免与章节编号混淆）

#### 5.8.7 符号与标注约定

普通词语和术语不加装饰性引号、反引号或方括号。保留真实引用、路径、命令、代码及必要 Markdown 结构；G1 规则源的模式定界引号和解析结构也须保留，不机械替换全文符号。

##### 义务、证据与状态

用简短陈述或状态列说明，不强制审计标签外形，不重复标记。按 G1 去掉转折否定铺垫，直接写可用范围、限制、条件和待验证项；保留真实引文、代码及协议义务。

| 内容 | 表达要求 |
|------|---------|
| 义务强度（参考 RFC 2119） | 必须表示绝对要求，应该表示强烈建议且说明偏离条件，可以表示可选，禁止表示不可执行；仅在需要区分义务时使用 |
| 实测与经验数据 | 按 G2 说明来源、时间；估算说明推导依据，判断说明推理依据，假设说明成立条件和失效后果 |
| 待验证或待实现确认 | 说明缺口、验证方式及已约定时间，或依赖的实现与确认条件；时间未定如实说明 |
| 目标、契约与标识符 | 目标和契约值说明性质；版本号、错误码、日期、编号免于逐数字标注 |
| 完成度 | 按实际状态写已完成、进行中、待开始、已阻塞或已取消；已完成须有验证依据，阻塞或取消说明原因 |

##### 关系符号

用于流程描述、架构说明中表达元素间的关系。

| 符号 | 语义 | 使用场景 |
|------|------|---------|
| `→` | 顺序/因果/数据流向 | "请求 → 网关 → 服务" |
| `←→` | 双向交互 | "前端 ←→ WebSocket 服务" |
| `\|` | 并行/独立 | "服务 A \| 服务 B（独立部署）" |
| `⊃` | 包含/归属 | "平台 ⊃ {认证模块, 权限模块}" |

仅在行内简述结构关系时使用。复杂流程用 Mermaid 图（5.8.2），不用符号堆砌。

##### 引用格式

| 引用对象 | 格式 | 示例 |
|---------|------|------|
| 本文档章节 | `§{编号}` 或 `见 {节名}` | "见 §3.2" "详见 取舍说明 一节" |
| 外部文件 | `见 {文件路径}` | "见 `docs/api-spec.md`" |
| 代码符号 | 反引号包裹 | "`getUserById()`" |
| 约束编号 | 直接引用 | "违反了 C3 判断义务" |

##### 列表约定

| 情况 | 使用 | 原因 |
|------|------|------|
| 有先后顺序的步骤 | 编号列表 `1. 2. 3.` | 编号显式表达顺序 |
| 无顺序的并列项 | 无序列表 `- - -` | 无序避免暗示不存在的优先级 |
| 有优先级的并列项 | 编号列表 + 显式标注优先级 | 编号可用于引用，优先级在内容中说明 |
| 列表项内嵌套 | 字母编号 `a. b. c.` 或无序 | 避免数字嵌套数字造成混淆 |
| 列表不易扫描 | 按主题分组或转为表格 | 以查找需要决定，不按条数强拆 |

##### 嵌入约定

| 嵌入类型 | 格式 | 规则 |
|---------|------|------|
| 代码片段 | ` ```语言 ` 代码块 | 标注语言，保留完整语法与条件 |
| 图表 | ` ```mermaid ` 代码块 | 遵循 5.8.2 规范 |
| 引用定义 | `> ` 引用块 | 用于术语定义、关键引用 |
| 注意事项 | `> **注意**：` | 读者可能忽略但影响正确性的信息 |
| 警告 | `> **警告**：` | 可能导致数据丢失或安全问题的操作 |
| 表格 | Markdown 表格 | 遵循 5.8.3 规范，按需补引导句 |
