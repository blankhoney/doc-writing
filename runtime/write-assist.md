# 编写辅助

这些指引只组织执行，不替代完整约束。包内路径相对本文件解析；读取目标项目材料时仍使用项目路径。

## 开始编写前

1. 确认已完整读取[约束体系](../docs/design-spec.md) §3，以及[索引](../templates/_index.md)中选定的类型模板。不能仅根据 H1–H9 推断其余规则。
2. 读取[模板指导](../docs/modules/5.2-document-templates.md) §5.2.1–5.2.7 的固定/定制边界、命名、深度与示例范围，以及[表达规范](../docs/modules/5.8-structured-expression.md)。D1 按当前类型与变体执行。
3. 读取[来源状态](../examples/SOURCES.md)，按登记用途使用真实来源、源码改编或构造示意。未核验草稿不作正向 few-shot；短样本不替代完整模板，示例不是目标项目事实。

## 按信息选择表达方式

按所选变体保留类型分工、锚定节、必需字段与固定格式；非固定顺序、表达及自定义模块按读者任务调整。项目正文按 C5 写项目本身，不以本轮修改或验证记录代替。按 5.8 组织真实关系，保留必要短段论证，不连续多段纯散文或逐段套列表、表格；无法确认时重读模板。

Quickstart 按准备阶段确定的读者任务组织：

- 首屏给真实主要功能的必要输入、最小可复制操作与结果确认；确认用户所得成果，不把作者的规则核对或检查记录审阅列为普通使用者的必做步骤。必要执行状态由作者另行说明，必要参数、环境、权限和保存条件不能省略。
- 自然语言接口先示范用户材料到目标产物，例如“根据我提供的材料，写一份操作指南”（仅为调用形式示意）。实际入口与必要输入按项目确定，不默认给内部工具写说明；默认行为、模板选型和内建检查由助手承担，不转交用户。用户定制与必要澄清保留，不预设长提示词或字数上限。
- 与当前任务无关的实现、进阶配置、扫描及手工验收细节后置，辅助依赖不阻断本可用的主要功能。用户明确要求扫描器等工具的指南时，按指定任务写；手动调用与写入授权仍须明确。

架构需解释组成、职责、边界与依赖时按 5.8.2 画 Mermaid 结构关系图，目录树或步骤图不能替代；一句可说清的简单关系不硬画，非架构不强制有图。按真实项目画模型与资源关系，交付前渲染并核对图是否回答本节问题；未能渲染如实说明。代码、配置、命令核对版本与环境，引用保留原貌。

## 写作中的检查

- 每节先明确结论或要点，再给支撑信息。参考文档不追加主观决策；纪要不替参与者新增理由或排序。
- 对数字和关键判断执行 G2：区分实测、估算、待验证以及事实、假设、判断。目标和契约值说明性质即可，版本号、状态码、日期、编号不逐一加实测标记。
- 每节完成后检查 G1、C6 与内容密度：用常用语言写对象、行为、条件与结果，不直接抛内部术语；必要术语、前置条件、鉴权契约和安全警告保留，不因重复次数删除。
- 义务、证据和状态按 5.8.7 用简短陈述或状态列说明，不强制标签；普通词语不加装饰符号，技术语法与真实引用保留。

进入[验证入口](verify-checks.md)。编写时已经注意某条约束，不代表收尾时可以省略检查；事实缺口不靠润色变成已知事实。
