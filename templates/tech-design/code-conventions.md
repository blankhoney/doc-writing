# 本次代码规范

用于新代码、代码级设计与改编示例；真实来源摘录保持原貌。先看项目规范与现有工具配置，再取目标模块、直接依赖、成熟同类实现及相关测试，不扫描全仓库求平均分。

## 依据与决定

| 维度 | 核对与交接 |
|---|---|
| 风格 | formatter/linter、导入、文件组织、语言惯用写法及注释语言；无工具时不自动安装 |
| 职责 | 模块边界、依赖方向、状态所有者、副作用；不照搬职责混杂或循环依赖 |
| 命名 | 领域词对应类型／函数／变量／文件；布尔、集合、单位、状态与缩写含义一致 |
| 类型 | 边界输入输出、字段、可空性、所有权和错误；按语言选类型、schema 或运行时校验，不引入不必要机制 |
| 可读性 | 控制流、参数和依赖可追踪；普通函数能满足时不加抽象，不设通用行数门槛 |
| 注释与验证 | 关键契约和理由有解释，与实现一致；沿用适用测试习惯，补当前变更的验证点 |

以可核查质量要求逐维度决定：合格惯例沿用；局部问题定点加强；混乱区域为本次新代码制定规则及旧接口映射；证据不足给草案与缺口。新项目没有源码时按需求、语言和已知约束拟定。不得虚构行业平均分。

将“依据位置／沿用或新定规则／适用范围／核验方式”写在设计原节，小任务用条目。公开名称、序列化字段、安全及构建约束继续满足；冲突进入未决，不擅改公共 API、关闭检查或格式化范围外代码。

## 主动注释

- 入口、公共接口和非显然的内部行为：补职责、前置条件、单位、所有权、副作用及错误，避免复述类型签名。
- 算法、状态、并发与事务：解释选择理由、不变量、顺序及锁／事务范围。
- 重试、超时、取消和清理：解释触发、停止、幂等、资源释放与失败后的可见状态。
- 兼容绕行和特殊常量：解释原因、依据、影响及移除条件；不编 TODO 负责人或日期。
- 伪代码省略项：标明仅示意的部分及实现必须补齐的条件。

主动补足上述适用重点注释，不因现有注释少而省略；改名和简化控制流不替代契约与理由说明。不逐行翻译代码、不设注释比例，纠正本次范围内过时注释。例：`offset += size  # 增加偏移量` 只复述动作；需要注释的是“只在整块写入成功后推进偏移，失败重试仍从原位置开始”这样的不变量（构造说明，不是项目事实）。

## 交付前核对

所选规则有依据、命名映射一致、边界类型清楚、关键行为有必要注释；样例符合目标语言与版本，验证与未验证项可分辨。写设计不自动授权修改目标源码。
