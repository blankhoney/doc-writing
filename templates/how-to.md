# How-to Guide（操作指南）
> 引导已具备基础知识的读者完成具体任务，保留必要术语解释，不展开无关教学。

> **示例使用范围**：保留已核验的 Django CSV 局部节译及本仓库扫描操作改编；分别示范实现片段与操作组织，不是目标项目事实或本次实测。见[来源说明](../examples/SOURCES.md)。

## 变体选择

```
文档的用途？
  ├─ 完成单个具体任务            → 任务食谱
  ├─ 运维/值班操作手册中的一条     → 操作手册条目
  └─ 同一领域多个任务的合集       → 食谱索引
```

默认走**任务食谱**。Quickstart 面向已有基础、只想用一次真实主要功能的读者时，沿用任务食谱，不转成 Tutorial。操作手册条目用于嵌入 Runbook；食谱索引用于文档站导航页。

## 变体 A: 任务食谱

> 一个任务、一个目标、一组步骤。读者知道要做什么，只需知道怎么做。用作 Quickstart 时，首屏给真实主要功能的最小可复制操作与结果确认，必要前提短放操作前；进阶配置、手工验收与扫描细节后置。保留手动调用与写入授权，不以辅助工具依赖阻断本可用的主要功能，也不把作者读规则或检查记录变成读者练习。

### 锚定节

| 锚定节 | 锚问 | 排版 |
|--------|------|------|
| **目标** | 这篇指南帮你完成什么？（一句话） | 倒金字塔：`本指南说明如何 [动作] + [结果]` |
| **前置条件** | 所需环境、权限、工具？ | 无序列表：每项一个检查命令或确认条件 |
| **步骤** | 怎么做？ | 有序步骤 + 验证信号 |

**步骤格式规范**：

- 每步是一个动作指令（祈使句），不是描述
- 关键步骤附验证信号（`确认：...`），非关键步骤可省略
- 步骤中只解释完成任务所需的术语与条件
- 允许条件分支（`如果你需要 X，执行 Y`），但分支不超过两层

与 Tutorial 的核心区别：
- Tutorial 禁止分支，How-to 允许条件分支
- Tutorial 每步都要验证信号，How-to 只在关键步骤加
- Tutorial 不假设读者知识，How-to 假设读者有基础

### 可插模块

| 模块名 | 锚问 | 排版 | 格式规范 | 有效性检验 |
|--------|------|------|---------|-----------|
| 变体分支 | 不同场景下步骤有什么不同？ | 条件分支（`如果 X → 步骤 Y`） | 每个分支：触发条件 + 替代步骤 + 回到主流程的汇合点 | 分支有明确触发条件和汇合点 → 有效；"也可以用 A"无条件 → 无效 |
| 故障排查 | 出错了怎么办？ | 定义列表 | 每条：错误现象 + 原因 + 修复步骤 | 每条有修复步骤 → 有效；"请联系管理员"→ 无效 |
| 相关任务 | 做完之后可能还要做什么？ | 无序列表 | 2-3 个链接，每个说明与当前任务的关系 | 链接存在且关系明确 → 有效 |
| 安全/权限提醒 | 执行这些步骤需要什么权限？有什么风险？ | 警告块 | `> **警告**：` + 具体风险 + 缓解措施 | 有具体风险和缓解措施 → 有效；"请谨慎操作"→ 无效 |

````markdown
# 使用 Python 的 CSV 库输出 CSV

Python 自带 csv 库。将其与 Django 配合使用的关键在于：
csv 的 CSV 生成功能作用于类文件对象，而 Django 的 HttpResponse 对象就是类文件对象。

示例：

```python
import csv
from django.http import HttpResponse


def some_view(request):
    # Create the HttpResponse object with the appropriate CSV header.
    response = HttpResponse(
        content_type="text/csv",
        headers={"Content-Disposition": 'attachment; filename="somefilename.csv"'},
    )

    writer = csv.writer(response)
    writer.writerow(["First row", "Foo", "Bar", "Baz"])
    writer.writerow(["Second row", "A", "B", "C", '"Testing"', "Here's a quote"])

    return response
```
````

## 变体 B: 操作手册条目

> 嵌入 Runbook 或运维手册的独立条目。比任务食谱更精简，假设读者是值班工程师。

### 锚定节

| 锚定节 | 锚问 | 排版 |
|--------|------|------|
| **触发条件** | 什么情况下执行这个操作？（告警名 / 症状） | 倒金字塔：告警名或症状描述 |
| **步骤** | 怎么做？ | 有序步骤 + 验证信号 |
| **升级路径** | 做不了 / 做完没用时找谁？ | 契约表：条件 → 联系人 |

**与任务食谱的区别**：
- 不单设"前置条件"节，所需环境、权限、工具在步骤前说明
- 触发条件替代目标（不是"我想做 X"而是"告警 Y 响了"）
- 必须有升级路径（值班不能卡住）

### 可插模块

| 模块名 | 锚问 | 排版 | 格式规范 | 有效性检验 |
|--------|------|------|---------|-----------|
| 影响评估 | 这个操作影响哪些服务/用户？ | 无序列表 | 每项：受影响对象 + 影响方式 | 列出具体服务名 → 有效；"可能影响用户"→ 无效 |
| 回滚 | 做错了怎么恢复？ | 有序步骤 | 与正向步骤对应的逆向操作 | 有具体命令 → 有效 |

## 变体 C: 食谱索引

> 同一领域多个任务的导航页。不包含步骤，只分类和指路。

### 锚定节

| 锚定节 | 锚问 | 排版 |
|--------|------|------|
| **领域说明** | 这个索引覆盖哪些任务？ | 倒金字塔：一句话范围 |
| **任务索引** | 每个任务在哪里？ | 索引 + 深链：按场景分类的链接表 |

**规则**：
- 每个链接一句话说明任务目标（不是文档标题复读）
- 按使用频率或场景分组，不按字母排序
- 不在索引页重复步骤内容

### 可插模块

| 模块名 | 锚问 | 排版 | 格式规范 | 有效性检验 |
|--------|------|------|---------|-----------|
| 前置阅读 | 开始这些任务前需要了解什么？ | 无序列表 | 链接到 Tutorial 或 Explanation | 链接存在 → 有效 |

## 类型验证标准（Phase 4 Step 1c）

### 结构检查

| 检查项 | 通过标准 | 违反时处理 |
|--------|---------|-----------|
| 不教无关基础 | 保留必要术语解释，不展开无关概念或原理 | 删除无关教学，必要时链到 Tutorial 或 Explanation |
| 聚焦"怎么做" | 每个段落都服务于完成任务，无历史背景、设计哲学、对比分析 | 删除与完成任务无关的内容 |
| 目标明确 | 标题或首句点明任务；Quickstart 任务食谱首屏可复制主要功能操作并确认结果，必要前提在前，辅助配置与手工验收在后 | 恢复最短任务，不用扫描演示替代用户目标，不把作者检查转交读者 |
| 步骤可执行 | 每步是祈使句动作指令，不是描述性陈述 | 改写为祈使句 |
| 前置条件完整 | 步骤前已说明所需环境、工具和权限 | 补充到步骤前 |

### Diátaxis 边界检查

| 检查项 | 违反信号 | 处理 |
|--------|---------|------|
| 不混 Tutorial | 展开与任务无关的基础教学，假设读者零基础 | 删除无关教学，前置条件中链到 Tutorial |
| 不混 Reference | 出现完整参数表、所有可选项列举 | 只保留当前任务需要的参数，链到 Reference |
| 不混 Explanation | 出现"为什么这样设计"、"历史上 X 导致了 Y" | 删除，必要时链到 Explanation |
