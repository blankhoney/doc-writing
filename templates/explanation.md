# Explanation（概念说明）
> 对一个主题的纵深讨论，帮助读者理解"为什么"——不给操作步骤，不列参数表，只建立心智模型。

> **示例使用范围**：本模板通过变体结构、锚定节、模块与类型验证标准使用，不附样本正文。见[来源说明](../examples/SOURCES.md)。

## 变体选择

```
要解释什么？
  ├─ 单个概念/机制的原理          → 概念解释
  ├─ 两个以上方案/技术的对比       → 对比分析
  └─ 一个设计/技术的演变历程       → 历史回顾
```

默认走**概念解释**。项目介绍与现有架构说明解释项目的组成、机制和设计理由；依据当前版本、面向验收人员，不等于改写本轮修改或验证过程。历史回顾只在演变本身是主题时选用，其他变体仍可保留解释当前设计所需的历史原因。

## 变体 A: 概念解释

> 解释一个概念、机制或设计决策的原理。回答"为什么是这样"而不是"怎么用"。

### 锚定节

| 锚定节 | 锚问 | 排版 |
|--------|------|------|
| **主题** | 这篇文章解释什么？读者读完能理解什么？ | 倒金字塔：一句话定义 + 读者读完会获得的理解 |
| **核心概念** | 该主题的核心机制是什么？为什么存在？怎么工作？ | 必要短段论证；分类、对应或流程按 5.8 组织，不连续多段纯散文 |
| **关联** | 这个概念和项目其他部分是什么关系？ | 架构的组成、职责、边界与依赖按 5.8.2 用 Mermaid 结构关系图；一句可说清的简单关系用短段 |

**核心概念的写法规范**：

- 从读者已知的概念出发，连接到新概念（锚定点教学法）
- 使用具体类比，但类比必须标注边界（"这个类比在 X 方面成立，但 Y 方面不同"）
- 论证有逻辑链：前提 → 推理 → 结论，不跳步
- 允许观点和判断，但按 G2 说明推理依据，与事实和假设区分；不强制标签
- 深度优于广度：核心概念必须包含完整的因果论证链（前提 → 推理 → 结论），而非定义罗列。一个概念论证完整优于五个概念各一句

### 可插模块

| 模块名 | 锚问 | 排版 | 格式规范 | 有效性检验 |
|--------|------|------|---------|-----------|
| 历史背景 | 这个设计是怎么演变到当前状态的？ | 时间线 | 关键转折点 + 每个转折的驱动因素 | 转折点有驱动因素 → 有效；只列时间和事件 → 无效 |
| 常见误解 | 关于这个概念最容易搞错什么？ | 差异对照 | `误解：X` vs `实际：Y` + 为什么容易搞错 | 有"为什么容易搞错"的解释 → 有效；只列正确说法 → 无效 |
| 与替代方案的关系 | 为什么不用 Y 而用 X？ | 短段论证，按需配比较表 | 表格对齐差异，文字说明取舍依据 | 有具体的取舍论证 → 有效；只有优劣或结论无理由 → 无效 |
| 深入阅读 | 想了解更多去哪里？ | 无序列表 | 每个链接标注"这份材料讲了什么、适合什么阶段的读者" | 有适用说明 → 有效；裸链接列表 → 无效 |
| 图解 | 本节需要解释哪些结构或机制？ | Mermaid 图 | 按 5.8.2 选择关系图，标题说明所回答的问题；简单关系不硬画 | 架构图回答所需结构问题并经渲染核对 → 有效；只有目录树、步骤图或只查图存在 → 不算完成结构检查 |

## 变体 B: 对比分析

> 两个以上方案/技术/架构的系统化对比。帮读者理解差异和取舍，不是推荐。

### 锚定节

| 锚定节 | 锚问 | 排版 |
|--------|------|------|
| **主题** | 对比什么？对比的维度是什么？ | 倒金字塔：对比对象 + 核心结论（一句话） |
| **核心概念** | 每个被对比对象的本质特征 | 按对象分组，必要机制用短段解释，不在描述阶段对比 |
| **对比** | 在每个维度上各自表现如何？ | 表格（维度 × 对象）+ 散文论证 |
| **关联** | 什么场景下选什么？ | 散文段落或决策树 |

**对比的规则**：
- 先独立描述每个对象，再对比（避免稻草人）
- 对比维度从实际需求推导（C4a），不用固定维度
- 表格展示事实差异，散文论证取舍逻辑
- 不给"最佳方案"结论（那是 ADR 的职责），给"什么情况选什么"

## 变体 C: 历史回顾

> 一个技术/架构/设计的演变历程。帮读者理解"为什么是现在这样"——不是编年史，是因果链。

### 锚定节

| 锚定节 | 锚问 | 排版 |
|--------|------|------|
| **主题** | 回顾什么的演变？当前状态是什么？ | 倒金字塔：当前状态 + "本文解释如何走到这里" |
| **核心概念** | 每个阶段的关键转变和驱动因素 | 时间线 + 散文：每个阶段的驱动因素 → 变化 → 结果 |
| **关联** | 当前状态的约束从哪里来？未来可能怎么演变？ | 散文段落 |

**历史回顾的规则**：
- 每个阶段必须回答"为什么从上一阶段变到这个阶段"（因果链，不是事件列表）
- 只讲对理解当前设计有影响的历史，不做完整编年史
- 标注哪些历史决策形成了当前的约束（"我们现在不能做 X 是因为 Y 阶段选了 Z"）

## 类型验证标准（Phase 4 Step 1c）

### 结构检查

| 检查项 | 通过标准 | 违反时处理 |
|--------|---------|-----------|
| 不混操作教程 | 不用让读者执行的步骤替代解释；可用分类编号、列表或流程图说明机制 | 操作教程移到 How-to 或 Tutorial，保留必要论证与真实结构 |
| 深度优于广度 | 核心概念部分有因果论证链，不是定义罗列 | 选择最关键的 1-2 个概念深入，删除浅述的条目 |
| 有具体性 | 机制与论证有具体案例、数据或代码依据；架构所需结构关系图按 5.8.2 回答本节问题并实际渲染核对 | 补证据或修正图，目录树与步骤图不能替代结构图；未能渲染说明未验证，简单关系不硬画 |
| 判断依据 | 主观判断与事实可分辨，按 G2 说明推理依据 | 补充依据，不用标签代替论证 |
| 主题有边界 | 第一段明确了"本文解释什么"和"不解释什么" | 补充范围声明 |

### Diátaxis 边界检查

| 检查项 | 违反信号 | 处理 |
|--------|---------|------|
| 不混 How-to | 出现"执行以下步骤"、祈使句操作指令 | 移到 How-to 文档，此处改为 `实现方式见 [How-to](链接)` |
| 不混 Reference | 出现参数表、配置清单、API 签名 | 移到 Reference 文档 |
| 不混 Tutorial | 出现"让我们来做一个"、学习路径、练习题 | 移到 Tutorial 文档 |

### 质量检查

| 检查项 | 通过标准 |
|--------|---------|
| 可离线阅读 | 读者不需要同时打开代码或终端就能理解内容 |
| 建立心智模型 | 读者读完能向他人解释这个概念的核心机制（不是复述定义） |
| 论证完整 | 每个"因为"都有对应的前提，不跳步 |
