# Reference（参考文档）
> 对系统及其操作方式的技术描述——只陈述事实，不加主观判断，结构镜像代码。

> **示例使用范围**：保留明确标注的键卡片构造示意，仅教格式与 JSON 语法，不对应实际软件或版本。见[来源说明](../examples/SOURCES.md)。

## 变体选择

```
文档描述的对象？
  ├─ 配置项 / 环境变量 / CLI 参数    → 键卡片
  ├─ 代码模块 / 类 / 函数           → 与代码同构
  ├─ 数据模型 / 状态 / 协议          → 模式表
  └─ 命令行工具                    → man page
```

默认走**键卡片**（覆盖最常见的配置和参数参考场景）。

---

## 变体 A: 键卡片

> 每个配置项/参数/字段一张卡片，固定字段结构。K8s API Reference、Stripe API 参数表模式。

### 锚定节

| 锚定节 | 锚问 | 排版 |
|--------|------|------|
| **范围声明** | 这份参考覆盖什么？版本号？ | 倒金字塔：一句话范围 + 版本/API 版本 |
| **键卡片序列** | 每个键是什么、接受什么值、默认什么？ | 定义列表 / 键卡片 |

**键卡片格式规范**（每张卡片必含字段）：

| 字段 | 说明 | 规则 |
|------|------|------|
| 键名 | 配置项/参数的完整标识符 | 使用代码中的实际名称，反引号包裹 |
| 类型 | 值的数据类型 | `string` / `int` / `bool` / `Duration` / 枚举列表 |
| 默认值 | 未设置时的值 | 写明具体值；无默认值写无（不等同于必填） |
| 必填 | 调用方是否必须提供 | 是 / 否 |
| 说明 | 这个键控制什么行为 | 一句话描述效果，不解释原理 |
| 约束 | 值的合法范围或限制 | 如 `≥ 0`、`最大 1024`、枚举值列表 |

可选字段（按需添加）：
- 示例：一个具体的有效值
- 环境变量：对应的环境变量名
- 引入版本：从哪个版本开始支持
- 废弃：废弃状态和替代方案

**排列规则**：
- 按代码中的逻辑分组（不按字母排序，除非代码本身无分组逻辑）
- 必填项排在可选项前面
- 同一分组内按使用频率降序

### 可插模块

| 模块名 | 锚问 | 排版 | 格式规范 | 有效性检验 |
|--------|------|------|---------|-----------|
| 为何存在 | 这组配置解决什么问题？ | 引用块 | `> 见 [Explanation 文档名](链接)` + 一句话摘要 | 链到真实的 Explanation 文档 → 有效；内联解释超过三句 → 无效（违反边界） |
| 完整示例 | 一个真实的配置文件的完整结构？ | 代码块 | 标注语言；只含当前范围的键；仅说明必要效果与条件：语法允许时内联注释，JSON 等不允许时放代码块外 | 可复制运行/加载 → 有效；伪代码或占位值 → 无效 |
| 版本变更 | 哪些键在近期版本中变了？ | 差异对照 | `旧键名 → 新键名` 或 `v2.0 新增` | 每条有版本号 → 有效 |
| 相关参考 | 与哪些其他配置有交互？ | 无序列表 | 每个链接说明交互方式（"X 的值影响 Y 的行为"） | 说明了具体交互 → 有效 |

### 示例

> 构造示意：假想配置仅含下列两键，展示键卡片、标准 JSON 与块外说明，不对应实际软件或版本。

````markdown
# 日志配置参考（构造示意）

范围：仅 `log_level` 与 `log_format`。

### `log_level`
- **类型**：`string`
- **默认值**：`info`
- **必填**：否
- **说明**：最低输出级别，低于此级别的日志被丢弃。
- **约束**：按级别递增为 `debug`、`info`、`warn`、`error`。

### `log_format`
- **类型**：`string`
- **默认值**：`json`
- **必填**：否
- **说明**：日志输出格式，不改变级别过滤。
- **约束**：仅 `json`、`text`。

## 完整配置
```json
{
  "log_level": "warn",
  "log_format": "json"
}
```
这组值仅输出 `warn` 与 `error` 级别的日志，格式为 JSON。
````

## 变体 B: 与代码同构

> 文档结构完全镜像代码结构（包/模块/类/方法），适合 SDK 和库的 API 参考。

### 锚定节

| 锚定节 | 锚问 | 排版 |
|--------|------|------|
| **范围声明** | 覆盖哪些包/模块？版本？ | 倒金字塔 |
| **模块/类/函数条目** | 每个公开 API 的签名、参数、返回值、异常 | 定义列表（嵌套） |

**条目格式规范**：

```
### `模块名.函数名(参数列表) → 返回类型`

参数：
- `param_name` (`类型`, 必填/可选, 默认值) — 一句话说明

返回：`类型` — 一句话说明

异常：
- `ErrorType` — 触发条件

示例：
（3-5 行可运行代码）
```

**结构规则**：
- 文档层级 = 代码层级（`包 > 模块 > 类 > 方法`）
- 公开 API 全部列出，内部 API 不列
- 如果可以从代码注释自动生成，标注生成命令

### 锚定节

| 锚定节 | 锚问 | 排版 |
|--------|------|------|
| **范围声明** | 描述什么模型/协议？版本？ | 倒金字塔 |

### 可插模块

| 模块名 | 锚问 | 排版 | 格式规范 | 有效性检验 |
|--------|------|------|---------|-----------|

## 变体 D: man page

> 命令行工具的参考页，遵循 Unix man page 惯例。

### 锚定节

| 锚定节 | 锚问 | 排版 |
|--------|------|------|
| **概要（SYNOPSIS）** | 命令的完整调用格式 | 代码块：`command [OPTIONS] <ARGS>` |
| **描述（DESCRIPTION）** | 这个命令做什么？（一段话） | 散文段落 |
| **选项（OPTIONS）** | 每个 flag/option 的含义和值 | 定义列表 |

**选项格式规范**：

```
### `-f`, `--format` <FORMAT>
输出格式。

**值**：`json` | `yaml` | `table`
**默认**：`table`
```

### 可插模块

| 模块名 | 锚问 | 排版 | 格式规范 | 有效性检验 |
|--------|------|------|---------|-----------|
| 示例（EXAMPLES） | 常用场景怎么调用？ | 代码块 | 每个示例：一句话场景 + 命令 + 输出 | 命令可运行 → 有效 |
| 环境变量 | 哪些环境变量影响行为？ | 键卡片 | 同变体 A 格式 | — |
| 退出码 | 不同退出码什么含义？ | 契约表 | `退出码 \| 含义 \| 常见原因` | 列出非零退出码 → 有效 |
| 另见（SEE ALSO） | 相关命令/文档 | 无序列表 | 每项一句话说明关系 | — |

## 类型验证标准（Phase 4 Step 1c）

### 结构检查

| 检查项 | 通过标准 | 违反时处理 |
|--------|---------|-----------|
| 结构镜像代码 | 文档的章节/分组与代码中的模块/类/配置分组一致 | 调整文档结构匹配代码组织 |
| 参数完整 | 每个公开的配置项/参数/字段都有条目 | 补充缺失条目 |
| 类型准确 | 类型标注与代码中的实际类型一致 | 以代码为准修正 |
| 默认值准确 | 标注的默认值与代码中的默认值一致 | 以代码为准修正；尚未确认时说明缺口与核实方式 |
| 无遗漏必填项 | 必填参数有独立的"必填"字段标注（不用"无默认值"代替） | 补充必填字段 |
| 格式统一 | 必需字段和固定排版一致，可选字段按需添加 | 保留固定要求，不把可选字段误当必填 |

### Diátaxis 边界检查

| 检查项 | 违反信号 | 处理 |
|--------|---------|------|
| 不混主观判断 | 出现"推荐"、"最佳实践"、"通常应该" | 删除判断，或移到 How-to/Explanation 并链接 |
| 不混操作步骤 | 出现"首先做 X，然后做 Y"的流程指引 | 移到 How-to 文档 |
| 不混概念解释 | 出现"这个配置的设计目的是"、"历史上因为 X" | 压缩为一句 `> 见 [Explanation](链接)` |
| 不讲故事 | 出现叙事性段落、场景描写、用户故事 | 删除，Reference 只陈述事实 |

### 质量检查

| 检查项 | 通过标准 |
|--------|---------|
| 可查阅性 | 读者能在 10 秒内通过搜索或扫描定位到目标条目 |
| 权威性 | 与代码实际行为一致（通过 5.3.1 内容对齐检查验证） |
| 无歧义 | 每个条目只有一种解读方式 |
