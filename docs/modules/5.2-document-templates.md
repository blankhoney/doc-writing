### 5.2 文档类型模板与示例

#### 5.2.1 模板架构：三级选择

模板通过类型、变体和模块三级选择，保留固定要求，开放非固定部分的定制：

```
Level 1: 类型选择 → 确定文档身份（PRD? 技术设计? ADR?）
Level 2: 变体选择 → 确定结构深度（备忘? Lean? 完整?）
Level 3: 模块定制 → 保留固定要求，按任务增改自定义模块
```

沿用标准技术文档分工；项目介绍、架构、使用与参考文档默认写项目本身，版本只界定事实范围，不因验收读者改成本轮修改记录。文档集群用索引连接变更、验证等对应文档，正文保留影响理解或使用的状态、链接及必要设计理由。所选变体的锚定节、必需字段与明确固定格式保留，其余按任务组织。

#### 5.2.2 排版类型（跨文类一等公民）

先按内容选择排版，再填章节；具体表达沿用 5.8。

| 排版类型 | 形态 | 适用场景 |
|---------|------|---------|
| 倒金字塔 | 第一段就能办事，细节递进往后 | PRD 目标、Changelog、会议决议 |
| 问题→方案→代价 | 问题、选择和代价相连；必要短段配合真实分类、对照或图 | 技术设计、ADR |
| 有序步骤 + 验证信号 | 编号命令，每步写"你应看到" | Tutorial、How-to、Runbook、测试步骤 |
| 定义列表 / 键卡片 | Name / Type / Default / Effect | 配置参考、API 字段、环境变量 |
| 契约表 | 输入、输出、错误码、约束 | API 端点、验收标准 |
| 时间线 | `HH:MM` 动作 → 结果 | 测试报告、事故复盘、会议纪要 |
| 差异对照 | Before / After 或 旧 / 新 | Changelog 迁移指南、非目标说明 |
| 决策日志 | 状态标记 + 一篇一事 | ADR |
| 索引 + 深链 | 目录只指路，正文不重复 | 文档集门户、API 概览 |

明确固定的格式须保留（如契约表字段）；其余按信息关系选择，不把排版建议锁为全文格式或固定顺序。

#### 5.2.3 锚定节与模块化内容系统

**锚定节**（不可删除）：定义文档身份的固定内容。删除锚定节会让文档丧失其类型身份。

**模块槽位**：按所选模块的必需字段、明确格式和有效性要求填写；允许增改自定义模块。未固定的顺序与内部表达可按读者任务调整，不把可选项误当必填。

```
[锚定] 问题陈述                    ← 不可删除
  ├─ [槽位 A] 可插入：背景补充 | 竞品分析 | 用户画像
[锚定] 方案                        ← 不可删除
  ├─ [槽位 B] 可插入：备选方案 | 性能评估 | 安全分析 | 迁移计划
[锚定] 代价与未决                   ← 不可删除
  ├─ [槽位 C] 可插入：里程碑 | 风险矩阵 | 依赖清单
```

**模块格式规范**：

| 字段 | 说明 |
|------|------|
| 模块名 | 如"备选方案"、"性能评估" |
| 锚问 | 该模块回答什么问题 |
| 排版 | 该模块使用的排版类型 |
| 格式规范 | 精确的结构要求 |
| 有效性检验 | 何时算有效、何时算填充 |

**有效性检验规则**（防止模块内容为填充）：

| 模块 | 有效 | 无效（删除该模块） |
|------|------|-------------------|
| 备选方案 | 是现实候选（曾被认真讨论、客户指定、或业界主流），且记录了淘汰依据 | 无人提出过也无使用记录，纯为凑数而列 |
| 风险分析 | 每条风险有概率评估和缓解措施 | "可能有性能问题"无后续 |
| 性能评估 | 有基准数字或估算依据 | "性能良好"无数据 |
| 迁移计划 | 有具体步骤和回滚方案 | "逐步迁移"无细节 |
| 时间线 | 有日期和交付物 | "后续推进"无节点 |

模块不通过有效性检验时的处理：
- 内容空洞、与范围无关或纯为凑数 → 删除该模块（C1）
- 与范围相关但信息不完整 → 保留已知事实，说明待验证内容与验证方式，不因缺少量化数据、缓解措施或时间节点而删除

此处理顺序适用于各模板的模块有效性检验；模板中的“无效/删除”不覆盖信息缺口的保留要求。备选方案可以在所有已比较维度上均不占优，只要它是现实候选且有淘汰依据，就应保留必要记录。

#### 5.2.4 变体选择机制

每个文档类型提供 2-5 种结构变体。默认按风险和范围选择，类型有特殊选择维度时以类型模板为准：

```
任务的范围和风险？
  ├─ 小改动，一周内完成        → 最轻变体（备忘 / Brief）
  ├─ 单团队功能               → Lean 变体（默认）
  ├─ 跨团队或有架构影响        → 完整变体
  └─ 外部客户 / 法规要求       → 合规变体（仅此时）
```

**默认走 Lean** 仅适用于按范围与风险选择的类型；知识传递按阅读任务选型。Quickstart 要最快使用真实主要功能：已有会话或工具基础、只想完成一次任务时选 How-to 任务食谱，要教学才选 Tutorial 最短路径。深度取决于必要条件与理解、执行需要；长文可用摘要导航，快速路径不因短样本而覆盖整篇长文。

#### 5.2.5 类型与变体总览

##### 工程生命周期文档

| 类型 | 变体 | 锚定节 | 主排版 |
|------|------|--------|--------|
| PRD | Brief → Lean → 完整 → 需求条目库 | 问题、目标+非目标、验收标准 | 倒金字塔 + 契约表 |
| 技术设计 | 备忘 → Lean / Google 式 → 内部 RFC → SDD | 目标+非目标、方案、代价 | 问题→方案→代价 |
| API 文档 | 快速调用 → 端点参考 → 资源模型 | 鉴权、端点、错误码 | 定义列表 + 契约表 |
| Changelog | Keep a Changelog → Release Note → PR Note | 版本+日期、Breaking、变更列表 | 差异对照 |
| 测试报告 | CI 报告 → 发布签核 → 测试计划 | 范围、结果数字、失败项、未测项 | 时间线 + 契约表 |
| 部署/Runbook | Deploy Guide → 告警 Runbook → 操作手册 → 交接包 | 前置、步骤+验证、回滚、联系人 | 有序步骤 + 验证信号 |
| ADR / 会议纪要 | 会议纪要 → 决策日志 → Nygard ADR → MADR → Y 型 | 决策一句话、理由、后果 | 决策日志 |

##### 知识传递文档（Diátaxis）

| 类型 | 变体 | 锚定节 | 主排版 |
|------|------|--------|--------|
| Tutorial | 最短路径 → 带配置 → 多语言分轨 | 学习目标、步骤、成功验证 | 有序步骤 + 验证信号 |
| How-to Guide | 任务食谱 → 操作手册条目 → 食谱索引 | 目标、前置、步骤 | 有序步骤 + 验证信号 |
| Reference | 键卡片 → 与代码同构 → 模式表 → man page | 键名、类型、默认值 | 定义列表 |
| Explanation | 概念解释 → 对比分析 → 历史回顾 | 主题、核心概念、关联 | 倒金字塔（变体） |

**Diátaxis 边界禁忌**（4 类型严格分离）：
- Tutorial 不混 Reference 细节，不堆参数表
- How-to 保留任务前提与必要术语，不展开无关教学
- Reference 不加主观判断，只陈述事实
- Explanation 不给操作步骤，不变成 How-to

会议纪要不是 ADR：纪要可丢，ADR 要进库且 Accepted 后不改（开新 ADR 替代）。

#### 5.2.6 每类型的不可变与可变

读者和用户需求可调整内容、深度、非固定格式及自定义模块，不限于术语和例子；这属于模板内定制，不覆盖固定要求。文件名、标题、术语沿用模板及项目已有约定，用户明确强制命名除外；没有规定时按内容准确命名，不新增命名体系。模板文件名是包内资源名，不等于生成文件名。

| 类型 | 锚定内容 | 按任务展开与边界 |
|------|----------|----------------|
| PRD | 受影响者、依据、目标与非目标、验收 | 小问题用简要需求；跨团队补场景、边界、依赖和取舍 |
| 技术设计 | 目标可验、非目标、决定与代价 | 小变更用备忘；复杂方案补职责、接口、流程、备选和迁移代价 |
| API 文档 | 鉴权、参数、成功/失败示例、错误码 | 多资源补限制、兼容契约与导航；教学链到 Getting Started |
| Changelog | 受众、日期/版本、破坏性变更 | 补影响与迁移，不为凑长度加入系统背景 |
| 测试报告 | 范围、结果、失败证据、未测项 | 签核或计划补环境、证据与覆盖，不从源码推断通过 |
| 部署/Runbook | 前置、命令、验证、回滚、联系人 | 多阶段补衔接与失败处理，操作单元可独立使用 |
| ADR / 纪要 | 真实决策、依据、后果 | ADR 一篇一项决策；纪要记录已有讨论，不扩成总设计 |
| Tutorial | 学习目标、前置、步骤、成功判据 | 补必要概念、阶段衔接与反馈，围绕一个学习目标 |
| How-to | 目标、前置、步骤 | 补动作链、分支和故障处理，围绕一个任务 |
| Reference | 名称、类型、默认值、必填 | 扩大契约覆盖与导航，不改成基础教程 |
| Explanation | 主题、概念、关联 | 展开机制、取舍与边界，不用步骤替代解释 |

#### 5.2.7 Few-shot 示例

**设计假设**：具体示例有助于表达一致，效果待实测；不声称示例比完整规则更有效。

**示例来源要求**：

| 适合 | 不适合 |
|------|--------|
| 一线成品切片（Stripe 一个端点、K8s 一个命令） | 聚合站/营销站内容 |
| 规范标准（Keep a Changelog 一个版本、Nygard ADR 一篇） | 咨询公司 20 页 PRD |
| 脱敏后的团队真实文档 | 未经验证的 AI 生成内容 |

短文样本展示完整有限任务；长文片段注明章节与省略范围；构造示意只教语法或排版。按关键行为差异取样，15–25 行是取样参考，不限制全文长度，不截断代码或必要条件，不要求填满全部变体。

> **来源状态**：Requests、Backstage、Django 的已核验范围及源码改编、构造示意的用途见[来源清单](../../examples/SOURCES.md)。新增外部示例先核验再收录；示例不作为目标项目事实。

##### 示例 1：同主题备忘与长设计片段

读取[技术设计模板](../../templates/tech-design.md)中的候选扫描器样本：备忘回答单一取舍，长设计片段展开职责、流程和代价。共享动作/图树示意见 5.8，操作与配置示例分别见 [How-to](../../templates/how-to.md) 和 [Reference](../../templates/reference.md)。

##### 示例 2：Changelog（Keep a Changelog 变体，Security 条目）

实际读取 [Changelog 模板](../../templates/changelog.md)中“已核验：Requests 2.31.0 Security 条目”，示例只在模板中维护一份；[来源记录](../../examples/SOURCES.md#requests-2310)保留固定版本、许可与翻译范围。

**结构要点**：版本与日期定位历史更新，Security 条目同时说明受影响范围、触发条件、不受影响的情况和行动顺序。该例不示范全部分类，也不把原文没有的 Breaking 或迁移步骤补出来。

##### 示例 3：Nygard ADR 的理由与决策句（局部）

实际读取 [ADR 模板](../../templates/adr.md)中“已核验局部：Backstage ADR003”，不再维护另一份未核验的 JWT 成品示例；[来源记录](../../examples/SOURCES.md#backstage-adr003)保留固定版本、许可与删节范围。

**结构要点**：用具体理由支撑决策，并保留例外。原文没有 Accepted 或日期，片段也不包含完整后果；不补造这些字段，不把局部样本宣称为完整 Nygard ADR 合格成品。实际任务仍执行状态、背景、决策和后果的全部适用要求。

default_variant: <默认变体名>
---

## 变体选择

#### 5.2.9 权威参考源分级

参考源分三类，不混用：

| 类型 | 定义 | 示例 |
|------|------|------|
| 教写法的规范 | 告诉你怎么写这类文档 | Diátaxis 原站、Keep a Changelog、Google Design Docs at Google |
| 成品信息架构 | 做得好的实际文档 | Stripe Docs、K8s API Reference、Django Tutorial |
| 字段模板 | 可填充的结构表 | GitLab issue templates、Nygard ADR 格式、MADR |

真实来源从一线成品取样；范围按 5.2.7，不使用聚合站转述。

**各类型推荐一线源**：

| 类型 | 教写法 | 成品/字段模板 |
|------|--------|-------------|

| 部署/Runbook | Google SRE Book/Workbook | K8s Configuration Best Practices |

#### 5.2.10 扩展机制

新增文档类型时：
1. 在 `templates/` 创建模板文件，遵循 5.2.8 规范
2. 在 `_index.md` 添加索引
3. 如有类型专用子规则，编号为 D{N}（D1 为架构文档质量清单）
4. L0 核心层不需要修改
