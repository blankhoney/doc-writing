### 5.3 验证管线详述

本节细化[验证入口](../../runtime/verify-checks.md)所载原 Phase 4（3.6）中各 Step 的具体检查逻辑；原收尾 3.5 也在该入口。

Phase 4 由**模型完整主检**与**小脚本候选定位**协作。模型读取全部适用约束，按原始收尾映射、V1–V5 和 L1 类型验证完成判断；脚本不替代任何语义检查。执行入口为 `runtime/verify-checks.md`。

```
Phase 4 开始 → 读取完整检查来源
    ↓
Step 1: 模型完整主检（含 V1-V5）+ 类型专用验证（5.3.5）
    └─ [直接调用] doc-lint.py 候选扫描 → 模型裁决
    ↓ 修正并复查
Step 2: 内容对齐（5.3.1）
    ↓ 修正并复查
Step 3: 叙述重复度（5.3.2）
    ↓ 修正并复查
Step 4: 读者测试（5.9，仅关键文档）
```

未解决或未执行的项目明确保留，不默认通过。

#### 5.3.1 内容对齐检查（Phase 4 Step 2）

**问题**：文档中对代码、架构、接口的描述可能与实际代码不一致。

**文档类型区分**：不同文档的权威来源不同。

| 文档性质 | 判定规则 | 不一致时处理 |
|---------|---------|------------|
| 实现描述类（API 文档、部署手册、Changelog、Reference） | 文档描述选定版本的实现 | 以对应版本的代码或接口契约为准更新文档 |
| 目标设计类（PRD、技术设计、ADR） | 文档描述目标状态 | 说明当前实现与目标的差异，不自动对齐 |
| 混合类（测试报告、How-to） | 按段落判断 | 结果数据以对应测试/运行记录为准；现有操作步骤核对对应版本，目标状态保留为目标 |

**检查项**：

| 检查对象 | 验证方式 | 处理 |
|---------|---------|------|
| 文档提及的函数名/文件路径 | Grep/LSP 确认存在 | 不存在则标记或修正（按文档类型区分处理） |
| 文档引用的接口定义/参数 | 与实际代码签名比对 | 不一致则按上表处理 |
| 文档引用的配置项/环境变量 | 在项目中搜索确认 | 不存在则说明待确认内容与核实方式 |
| 架构图中的组件名称 | 核对图文是否指向同一概念及其实现映射 | 仅修正同一概念的命名或映射错误，不要求概念组件与源码目录同名 |
| 测试/运行结果 | 核对对应提交、流水线或日志中的实际执行记录 | 不从源码推断已执行或已通过；缺少记录时说明待验证内容与验证方式 |

**前置判定**：执行内容对齐前，先确定本文描述的是哪个版本/时间点（当前行为、历史版本、还是目标状态），以及对应证据来源是什么（当前分支、已发布 SDK、设计稿）。不默认以当前工作区代码为权威——历史 Changelog 对齐到当前分支会改坏真实记录。

**适用条件**：文档引用具体代码、配置或实际运行结果时执行，快速路径同样适用；没有此类引用时跳过，其他数据的来源与标注按 G2/V2 核验。尚无代码的目标设计不要求虚构实现证据。架构图中的组件名称是概念标识，一个概念组件可对应多个源码模块，不构成术语错误。

#### 5.3.2 叙述重复度检查（Phase 4 Step 3）

**问题**：AI 在长文档中倾向于在不同章节重复相似内容，尤其是结论和关键判断。

**适用条件**：纯文本自检，不依赖代码上下文。所有文档类型均执行。

**检查方式**：主 agent 自检——逐章节扫描，识别跨章节的语义重复（不是字面重复，而是换说法的同一信息）。

**判定标准**：

- 先按实际阅读方式确定阅读单元（如一条操作条目、一个端点或一条语言轨道）。同一阅读单元内，同一信息出现 >2 次且没有新增用途 → 保留信息最完整的一处，其余删除或改为引用
- 豁免条件：摘要与正文的合理重叠；不同独立阅读单元必需的前置条件、鉴权契约、操作步骤和安全警告。不能只按全文出现次数删除，也不要求读者跨单元查找执行所需信息

#### 5.3.3 脚本辅助（Phase 4 由工作流直接调用）

**定位**：单个 `runtime/doc-lint.py` 用 Python 3 标准库定位候选。模型始终检查完整规则；脚本和 Python 不可用或执行被拒绝时，说明未执行原因，由模型完成检查，不绕过权限。不使用 hook。

**保留检查要求，区分执行责任**：

| 检查 | 对应规则 | 执行方式 |
|------|---------|---------|
| 禁用句式扫描 | G1 全部句式 | 模型完整检查，脚本补充纯字面片段候选 |
| 禁用修饰词扫描 | G1 修饰词 | 脚本定位，模型判断度量条件 |
| 禁用大词扫描 | G1 大词 | 脚本定位，模型判断定义和必要性论证 |
| 术语一致性 | C6 | 模型检查名称、首次定义与含义一致性 |
| 对称性检测 | C1a | 模型按内容权重判断，不以字数方差判违 |
| 结构化表达 | 5.8 | 模型按 3.5 #11 检查模板固定/定制边界、真实结构、必要短段、图文及符号用途 |
| 标题空泛检测 | V1 | 模型对照标题与内容判断 |
| 格式一致性 | 排版规范 | 脚本提示中文标点、间距和括号候选，模型裁决 |

**输出与豁免**：所有命中均为候选，默认警告，不自动改写。脚本有限排除代码、URL 和开头元数据；块引用不自动全部豁免。`<!-- doc-lint: ignore-next-line 原因 -->` 只影响下一物理行的候选，不豁免模型检查。`--skip-format` 可停用某类格式检查；细节见 5.1.3 及包内 README。

**执行结果**：退出 `0` 表示扫描完成，退出 `2` 表示执行故障；规则源缺失或解析失败不能当作无命中。脚本没有候选不代表完整检查通过，复杂句式、G2/G3、C3/C4 和所有语义边界仍由模型判断。

#### 5.3.4 滑动检查（长文档适用）

**设计假设**：长文一次生成可能遗漏后段约束；逐节检查能否减少遗漏待实测。

**机制**：逐节编写时（Phase 3 已要求），每完成一节执行局部检查：

- 启发式 H1（信息密度）自检
- 术语一致性（与前文已用术语比对）
- 对称性（当前节与前文的段落长度分布是否趋同）

这不是独立的验证步骤，而是编写阶段的内嵌检查，已整合到[编写入口](../../runtime/write-assist.md)的原 Phase 3 "编写粒度"规则中。

#### 5.3.5 类型专用验证（Phase 4 Step 1c）

**问题**：语义验证（V1-V5）检查通用写作规范，但不同文档类型有不同的质量关注点。PRD 需要检查成功条件是否可验证（数量型目标核对指标），API 文档需要检查参数定义是否完整——这些不在通用验证中。

**机制**：每个文档类型的模板文件（5.2）中包含"类型验证标准"字段。Phase 4 Step 1 执行 V1-V5 语义验证后，额外执行当前类型的专用验证项。

**执行方式**：

```
Phase 4 Step 1:
  a. 模型完整主检 — 原始收尾项按 5.1.4 映射执行
  b. V1-V5 组织语义判断 — 与 a 合并，不重复检查
  c. 类型专用验证 — 从当前加载的 L1 模板中读取
  补充：直接调用候选脚本 → 模型逐项裁决
```

**验证结构**：工程文档采用单表结构（检查项 + 判定标准）。Diátaxis 四类型采用二至三层结构（结构检查 + Diátaxis 边界检查 + 质量检查），边界检查验证类型隔离（如 Tutorial 不混 Reference 细节）。How-to Guide 的结构检查已覆盖核心质量关注点（步骤可执行、目标明确），采用二层结构。

**变体适用性**：同一类型的不同变体共享类型验证标准，但部分检查项仅适用于特定变体。模型应根据当前选定的变体跳过不相关的验证项（如 PR Note 无需检查"版本号可追溯"、"日期格式统一"等 Keep a Changelog 专属项）。

类型专用验证的检查项在各模板文件的"类型验证标准"字段中定义（见 5.2.8 模板文件规范）。以下是各类型验证的重点汇总：

| 文档类型 | 专用验证重点 |
|---------|------------|
| PRD | 成功条件是否可验证？数量型目标是否有指标？范围是否含"非范围"？需求能否验证完成？ |
| 技术设计 | D1 必答问题覆盖？取舍通过排除性检验？组件命名具体？ |
| API 文档 | 参数有类型+约束？错误码有行动指导？路径与代码一致？ |
| Changelog | Breaking Changes 醒目？每条有具体影响？无模糊汇总？ |
| 测试报告 | 统计单位与各指标分母（跳过／unknown／error／N/A 不计作通过）？失败有原因或已确认下一步？遗留风险有影响范围与依据？证据与结果同版本同运行？细则见 `test-evidence-presentation.md` |
| 部署手册 | 步骤可执行？回滚有命令？配置有示例值？ |
| ADR | 决策在前 3 段？理由通过排除性检验？有状态标记？ |
| Tutorial | 每步有成功信号？无概念堆砌？无读者选择？（三层验证） |
| How-to Guide | 前提、必要术语和动作是否清楚？是否混入无关教学？（二层验证） |
| Reference | 结构镜像代码？参数完整？（三层验证） |
| Explanation | 无操作步骤？深度优于广度？（三层验证） |

**与渐进式披露的关系**：类型验证标准随 L1 模板一起读取。未指定类型时先按索引匹配；确属未覆盖的新类型时仍执行完整模型检查和候选扫描，并说明缺少该类型的专用标准，不用脚本结果替代。
