### 5.1 渐进式披露

**问题**：完整约束体系包含核心约束、边界护栏、领域子规则、检查清单、表达规范、验证管线和读者测试。需要让模型读到全部适用规则，又不在入口中复制所有文档类型和参考资料。

> **首版执行原则**：保留完整约束，不以 token 预算裁剪规则。早期预算和压缩收益属于设计估算，不作为模型注意力或遵守率结论。渐进式披露用于组织资料，不代替实际读取。

**解决方案**：三个互补机制——
1. **行为启发式提示**（5.1.2）：保留 H1–H9，帮助执行，但不替代原始约束。
2. **脚本辅助**（5.1.3）：本地脚本定位字面和格式候选，模型完成全部上下文判断；不承诺固定数量的机械覆盖。
3. **按阶段读取**（5.1.1）：开始时读取完整约束和所选模板，编写及验证阶段读取对应指引；不增加按规则数量拆批的调度。

#### 5.1.1 加载架构

##### 分层概览

| 层级 | 名称 | 内容 | 加载条件 |
|------|------|------|---------|
| L0-init | 手动入口 | 工作流、完整约束读取要求、G2 优先级 | 用户调用 `/doc-writing` 时 |
| 原始约束 | 完整规则 | design-spec.md §3，包括 C/G/D 和原始收尾清单 | 编写前完整读取，验证时重新核对 |
| L0-write | 编写辅助 | 符号与标注约定、表达规范读取指引 | Phase 3 开始时 |
| L0-check | 验证入口 | 完整检查责任、V1–V5 与原始收尾项映射、类型验证指引 | Phase 4 开始时 |
| L1 | 类型层 | 文档类型模板、领域子规则、类型验证 | Phase 1 确定文档类型后 |
| L2 | 参考层 | 表达形式矩阵、Mermaid 规范、读者测试详述 | 按需 Read |

完整约束和候选输出都会占用上下文，不能再用“脚本执行所以规则不占 prompt”估算负担。实际用量与效果在真实任务中验证；不把上下文大小等同于遵守保证。

##### L0-init 手动入口

用户手动调用后加载 `SKILL.md`。入口要求实际读取完整 §3 和当前模板；H1–H9 作为行动提示保留，不是不可展开的压缩替代物。普通写作请求不自动启用本 skill。

##### L0-write 编写辅助（Phase 3 加载）

`runtime/write-assist.md` 指向 5.8 表达规范，包括符号与标注约定、表达形式选择及 Mermaid 的适用条件。此层组织查阅顺序，不另维护一套规则正文。

##### L0-check 验证入口（Phase 4 加载）

`runtime/verify-checks.md` 要求模型完整检查原始约束、收尾项及当前类型标准。以 5.1.4 映射组织一次检查，不把原始清单与 V1–V5 重复执行。

模型主检后，由工作流调用候选脚本补充位置，再逐项裁决。脚本不可用时仍执行完整模型检查并说明原因；不使用 hook。

##### L1 类型层（Phase 1 加载）

主模型按入口指令实际 Read 选定模板。文件存在不会自动加载。每个类型文件保留结构模板、变体选择、锚定节与可插模块、类型验证标准（见 5.2）。

##### L2 参考层（按需加载）

主 agent 按任务读取现有包内资料，不复制出另一套参考目录：

| 触发场景 | 加载文件 |
|---------|---------|
| 编写阶段选择表达形式 | `docs/modules/5.8-structured-expression.md` §5.8.1 |
| 需要画 Mermaid 图 | 同文件 §5.8.2 |
| 进入读者测试（Phase 4 Step 4） | `docs/modules/5.9-reader-testing.md` |
| 使用示例 | `examples/SOURCES.md`，按登记状态与用途采用 |

#### 5.1.2 行为启发式压缩

**设计来源**：i-have-adhd skill 用 10 条行动指令覆盖了数十条 ADHD 适应规则。ponytail skill 用一条启发式规则"删除优于添加"覆盖了填充、范围蔓延、过度工程三类问题。

**原理**：将规则组织为行动提示，帮助模型执行。是否比完整约束单独使用更可靠仍需实测；首版同时要求读取完整规则，不用启发式代替禁用清单和边界条件。

##### 9 条启发式（提示 C1-C6 + 子规则 + G2 + G3）

| # | 启发式 | 行动指令 | 覆盖的原始规则 |
|---|--------|---------|---------------|
| H1 | 信息密度 | 删除后读者理解不变的句子，删除它。段落长度反映内容权重，不追求形式对称。每段只说一件事。与范围相关但信息不完整时，保留已知事实并标注缺口；模板的“无效/删除”规则不得将这类信息当作填充删除。 | C1, C1a, C1b |
| H2 | 结论先行 | 每个章节和论证段落，先给结论再给论据。 | C1c |
| H3 | 绑定事实 | 每个判断绑定可观测事实。经验数据说明来源与时间，估算说明推导依据，缺口说明验证方式；目标值、契约值说明是要求或约定，版本号、错误码、日期、编号免于逐数字标注。影响决策的论述区分事实、假设、判断。 | C2, G2 标注 |
| H4 | 明确立场 | 文档职责要求决策或建议时，给明确判断并说为什么；参考文档陈述契约，纪要记录实际决议，不代替参与者作决定。验证已有判断：把结论换成反面，论据是否需要重写？如果不需要——论据没有真正支持结论。 | C3, C3a, G3 |
| H5 | 排序取舍 | 决策或建议场景中，多目标必须排序并说明依据；关键选择说明为了什么、牺牲了什么。记录类文档保留已有排序和取舍，不自行新增。 | C3b, C3c |
| H6 | 可操作性 | 每个概念能回答"具体做什么"或"具体不做什么"。不能回答的概念、原则、组件名称，删除。分析维度从问题推导，不套预设模板。 | C4, C4a |
| H7 | 范围锁定 | 开头声明本文覆盖什么、不覆盖什么；决策文档说明决定什么、不决定什么。此后每段服务于此范围。范围外的内容即使正确也删除。 | C5 |
| H8 | 真实优先 | 宁可说明待验证，不可为满足具体化要求而编造数据。优先级：真实性 > 具体化。 | G2 B>A |
| H9 | 句子直达 | 主语做动词，不绕弯。代词指代不明时用原词。每句只说一件事。每段首句亮出要点。列表条目语法并行，动作步骤以祈使动词开头。 | C1d |

##### 执行责任映射

下表保留原始规则各层的检查责任，不作为规则总数或可靠性统计。完整约束、适用条件与豁免仍以 §3 为准。

| 原始层 | 启发式提示 | 模型检查 | 脚本辅助 |
|--------|-----------|---------|---------|
| C1-C5 主规则 | H1-H7 | 全部适用要求 | — |
| C6 主规则 | — | 命名、首次定义和含义一致性（V1） | — |
| 子规则 | H1(C1a/b), H2(C1c), H4(C3a), H5(C3b/c), H6(C4a), H9(C1d) | 逐项核对原文 | — |
| G1 禁用模式 | H1+H9（原则层） | 完整句式与条件判断 | 纯字面片段和词项候选 |
| G2 规则+标注 | H3+H8 | 来源、认知状态及豁免（V2） | — |
| G3 排除性检验 | H4 | 判断是否被理由支持（V3） | — |
| 收尾检查 | — | 原始 11 项按 5.1.4 合并执行 | 不替代任何模型检查责任 |
| 格式一致性 | — | 中文正文、代码和引用的上下文判断 | 默认警告，可关闭单类格式扫描 |

**C6 补充说明**：命名变体、首次定义和含义是否一致均由模型检查。首版不实现词频聚类；脚本没有候选不等于 C6 通过。

##### 启发式与原始约束的关系

§3 是完整规则来源，保留设计理由和边界条件。H1–H9 是行动提示；模型在编写前实际读取完整 §3，验证时重新核对，而不是只在遇到边界时才读取。

#### 5.1.3 脚本辅助

**设计取舍**：保留所有质量规则，只缩小脚本责任。字面扫描有助于定位，语义判断仍由模型承担；不为达到固定数量增加算法。

##### 各类检查的执行方式

| 检查 | 对应规则 | 首版执行方式 |
|------|---------|-------------|
| 禁用句式扫描 | G1 句式清单 | 模型完整检查；脚本仅定位纯字面片段，不自动编译占位符或跨句模板 |
| 禁用修饰词扫描 | G1 修饰词 | 脚本定位词项；模型判断有无度量 |
| 禁用大词扫描 | G1 大词 | 脚本定位词项；模型判断定义、具体变化和必要性论证 |
| 术语一致性 | C6 | 模型判断同一概念的命名和含义，不做词频聚类 |
| 对称性检测 | C1a | 模型判断内容是否为凑形式而填充，不用字数方差判违 |
| 结构化表达 | 5.8 | 模型按阅读单元检查真实结构与必要短段，纠正连续多段纯散文及逐段套列表、表格 |
| 标题空泛检测 | 收尾#2、V1 | 模型对照标题与正文判断，不用标题大词命中判违 |
| 格式一致性 | 排版规范 | 脚本提示标点、间距、括号候选，模型结合文档规范裁决 |

##### 执行方式

```
Phase 4: 模型完整主检
    ↓
[工作流直接调用] runtime/doc-lint.py 扫描当前稿
    ↓
输出：文件:行号:类别:命中文本
    ↓
模型逐项修正、按上下文保留或标为需确认
```

**误报处理**：全部输出均为候选，不把字面命中当作已确认违规。脚本不改写输入。退出 `0` 表示扫描完成，退出 `2` 表示执行故障；无候选不代表质量通过。

##### 脚本设计原则

- 单个 Python 3 标准库脚本，无第三方依赖、无配置框架、无自动安装。
- 直接从包内 §3 的 G1 表和词项列表读取候选词源，不另维护硬编码词表或新规则 ID；必要结构解析失败必须报错。
- 有限排除围栏代码、行内代码、URL 和开头元数据，保留原始行号。块引用及链接可见文本不全部豁免。
- `<!-- doc-lint: ignore-next-line 原因 -->` 仅影响下一物理行的脚本候选，并报告应用情况；不豁免模型检查。
- 中文格式默认警告；`--skip-format` 可重复选择 `punctuation`、`spacing`、`parentheses`。Python、脚本或权限不可用时由模型完整检查并说明未执行原因。

#### 5.1.4 收尾检查合并

原始 11 项均保留检查责任；V1–V5 组织相近的语义检查，其余要求在同一次模型主检中执行。H1–H9 和脚本均不能替代收尾检查，运行时入口为 `runtime/verify-checks.md`。

##### 合并映射

| 原始收尾项 | 处理方式 | 去向 |
|-----------|---------|------|
| #1 禁用清单扫描 [G1] | 模型完整核查，脚本补充字面候选 | 模型主检 |
| #2 标题检验 [C1] | 保留（需语义判断） | V1 |
| #3 首尾检验 [C1c] | 检查实际正文，不只依赖编写时 H2 | 模型主检 |
| #4 数字检验 [G2] | 合并到 V2 | V2 |
| #5 认知状态检验 [G2] | 合并到 V2 | V2 |
| #6 判断检验 [C3+G3] | 保留 | V3 |
| #7 可操作性检验 [C4] | 保留 | V4 |
| #8 范围检验 [C5] | 保留 | V5 |
| #9 对称性检查 [C1a] | 按内容权重判断是否填充 | 模型主检 |
| #10 术语检查 [C6] | 名称、定义和含义一起核查 | V1 |
| #11 结构化表达检查 [5.8] | 核对模板固定/定制边界、真实结构、图文及符号用途（3.5） | 模型主检 |

##### 合并后 5 条语义验证（L0-check）

| # | 验证项 | 检查内容 |
|---|--------|---------|
| V1 | 标题与术语 | 标题是否准确？术语定义、命名与含义是否一致，用词是否易懂（C6）？ |
| V2 | 证据与状态完整性 | 经验数据和估算的性质、来源或依据是否清楚，缺口是否说明验证方式？目标值、契约值说明是要求或约定，版本号、错误码、日期、编号免于逐数字标注。事实、假设、判断可分辨，不靠标签代替依据？ |
| V3 | 判断强度 | 文档职责要求决策或建议时，作者的判断通过排除性检验，多目标有排序依据？参考文档不追加主观判断，纪要中的决议、排序和理由与原始记录一致？ |
| V4 | 可操作性 | 有概念、原则或组件名称无法回答"具体做什么/不做什么"？ |
| V5 | 范围一致性 | 有段落讨论了文档开头声明范围之外的内容？ |

##### 执行总负担

| 执行者 | 阶段 | 责任 | 验证边界 |
|--------|------|------|---------|
| 模型（L0-init） | Phase 1-3 编写 | 读取完整规则，H1–H9 作提示 | 不从指令数量推断可靠性 |
| 模型（L0-check） | Phase 4 验证 | 全部适用约束、V1–V5、收尾项和当前类型验证 | 未覆盖的范围明确标注，不默认通过 |
| 脚本 | Phase 4 由工作流调用 | 字面与格式候选定位 | 不执行语义裁决，不证明全文质量 |
| 主模型 | 修正与交付 | 复核候选、重验受影响项目、说明缺口 | 整体效果仍需真实任务验证 |

#### 5.1.5 轻量快速路径

**问题**：备忘/Brief 级文档仍需走完整 5 Phase 流程（30+ 检查点），与"快速记录"的定位矛盾。

**机制**：为最轻变体增加一条快速路径，跳过不必要的 Phase。

```
快速路径触发条件：变体 ∈ {Brief, 备忘, PR Note, 决策日志, CI 报告}

Phase 1: 选类型+变体 → 骨架（跳过读者角色定义）
Phase 2: 优先使用已有材料和本地证据，可省事实卡片格式；事实缺口仍按 5.6 路由补齐
Phase 3: 正常编写（启发式仍适用）
Phase 4: 模型完整主检（含 V1-V5）+ 类型专用验证 + 脚本候选裁决；有代码、配置或实际运行结果引用时执行 Step 2；执行 Step 3 叙述重复度，跳过 Step 4
Phase 5: 不另附缺口汇总；正文中的待验证内容和未决事项仍保留
```

**效果**（设计假设，待实测验证）：省去事实卡片包装、读者测试和单独的缺口汇总，不再按固定检查点数量估计节省。必要核验量取决于实际引用的材料。

**不降级的原则不变**：快速路径不跳过真实性要求和必要证据核验，信息源路由与标准路径相同（9 条启发式始终生效）。CI 报告必须依据对应流水线或日志，不从本地源码推断测试结果。

#### 5.1.7 运行时行为

- 仅在手动调用时加载 L0-init；随后实际读取完整 §3 和当前模板，不自动介入无关任务
- Phase 1 确定文档类型 → 加载对应 L1 模板
