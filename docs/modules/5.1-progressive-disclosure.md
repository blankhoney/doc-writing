### 5.1 渐进式披露

**问题**：完整约束体系包含核心约束、边界护栏、领域子规则、检查清单、表达规范、验证管线和读者测试。需要让模型读到全部适用规则，又不在入口中复制所有文档类型和参考资料。

> **首版执行原则**：保留完整约束，不以 token 预算裁剪规则。早期预算和压缩收益属于设计估算，不作为模型注意力或遵守率结论。渐进式披露用于组织资料，不代替实际读取。

**解决方案**：三个互补机制——
1. **行为启发式提示**（5.1.2）：保留 H1–H9，帮助执行，但不替代原始约束。
2. **脚本辅助**（5.1.3）：本地脚本定位字面和格式候选，模型完成全部上下文判断；不承诺固定数量的机械覆盖。
3. **按阶段与条件读取**（5.1.1）：共同约束先读；完整原文按实际动作前置，文类模板完整读取，内容分支按需进入；不增加按规则数量拆批的调度。

#### 5.1.2 行为启发式压缩

**设计来源**：i-have-adhd skill 用 10 条行动指令覆盖了数十条 ADHD 适应规则。ponytail skill 用一条启发式规则"删除优于添加"覆盖了填充、范围蔓延、过度工程三类问题。

**原理**：将规则组织为行动提示，帮助模型执行。是否比完整约束单独使用更可靠仍需实测；首版同时要求读取完整规则，不用启发式代替禁用清单和边界条件。

##### 9 条启发式（提示 C1-C6 + 子规则 + G2 + G3）

| # | 启发式 | 行动指令 | 覆盖的原始规则 |
|---|--------|---------|---------------|
| H1 | 信息密度 | 删除后读者理解不变的句子，删除它。段落长度反映内容权重，不追求形式对称。每段只说一件事。与范围相关但信息不完整时，保留已知事实并标注缺口；模板的“无效/删除”规则不得将这类信息当作填充删除。 | C1, C1a, C1b |
| H2 | 结论先行 | 每个章节和论证段落，先给结论再给论据。 | C1c |
| H3 | 绑定事实 | 每个判断绑定可观测事实。经验数据说明来源与时间，估算说明推导依据，缺口说明验证方式；目标值、契约值说明是要求或约定，版本号、错误码、日期、编号免于逐数字标注。影响决策的论述区分事实、假设、判断。 | C2, G2 标注 |
| H4 | 明确立场 | 文档职责要求决策或建议时，给明确判断并说为什么；参考文档陈述契约，纪要记录实际决议，不代替参与者作决定。验证已有判断：把结论换成反面，论据是否需要重写？如果不需要——论据没有真正支持结论。 | C3, C3a, G3 |
| H5 | 排序取舍 | 决策或建议场景中，多目标必须排序并说明依据；关键选择说明为了什么、牺牲了什么。记录类文档保留已有排序和取舍，不自行新增。 | C3b, C3c |
| H6 | 可操作性 | 每个概念能回答"具体做什么"或"具体不做什么"。不能回答的概念、原则、组件名称，删除。分析维度从问题推导，不套预设模板。 | C4, C4a |
| H7 | 范围锁定 | 开头声明本文覆盖什么、不覆盖什么；决策文档说明决定什么、不决定什么。此后每段服务于此范围。范围外的内容即使正确也删除。 | C5 |
| H8 | 真实优先 | 宁可说明待验证，不可为满足具体化要求而编造数据。优先级：真实性 > 具体化。 | G2 B>A |
| H9 | 句子直达 | 主语做动词，不绕弯。代词指代不明时用原词。每句只说一件事。每段首句亮出要点。列表条目语法并行，动作步骤以祈使动词开头。 | C1d |

#### 5.1.3 脚本辅助

**设计取舍**：保留所有质量规则，只缩小脚本责任。字面扫描有助于定位，语义判断仍由模型承担；不为达到固定数量增加算法。

##### 各类检查的执行方式

| 检查 | 对应规则 | 首版执行方式 |
|------|---------|-------------|
| 禁用句式扫描 | G1 句式清单 | 模型完整检查；脚本仅定位纯字面片段，不自动编译占位符或跨句模板 |
| 禁用修饰词扫描 | G1 修饰词 | 脚本定位词项；模型判断有无度量 |
| 禁用大词扫描 | G1 大词 | 脚本定位词项；模型判断定义、具体变化和必要性论证 |
| 术语一致性 | C6 | 模型判断同一概念的命名和含义，不做词频聚类 |
| 对称性检测 | C1a | 模型判断内容是否为凑形式而填充，不用字数方差判违 |
| 结构化表达 | 5.8 | 模型按阅读单元检查真实结构与必要短段，纠正连续多段纯散文及逐段套列表、表格 |
| 标题空泛检测 | 收尾#2、V1 | 模型对照标题与正文判断，不用标题大词命中判违 |
| 格式一致性 | 排版规范 | 脚本提示标点、间距、括号候选，模型结合文档规范裁决 |

##### 执行方式

```
Phase 4: 模型完整主检
    ↓
[工作流直接调用] runtime/doc-lint.py 扫描当前稿
    ↓
输出：文件:行号:类别:命中文本
    ↓
模型逐项修正、按上下文保留或标为需确认
```

**误报处理**：全部输出均为候选，不把字面命中当作已确认违规。脚本不改写输入。退出 `0` 表示扫描完成，退出 `2` 表示执行故障；无候选不代表质量通过。

##### 脚本设计原则

- 单个 Python 3 标准库脚本，无第三方依赖、无配置框架、无自动安装。
- 直接从 `docs/modules/constraints-writing.md` 的 G1 表和词项列表读取候选词源，以 G1/G3 标题为边界，不另维护硬编码词表或新规则 ID；必要结构解析失败必须报错，不回退旧主规格。
- 有限排除围栏代码、行内代码、URL 和开头元数据，保留原始行号。块引用及链接可见文本不全部豁免。
- `<!-- doc-lint: ignore-next-line 原因 -->` 仅影响下一物理行的脚本候选，并报告应用情况；不豁免模型检查。
- 中文格式默认警告；`--skip-format` 可重复选择 `punctuation`、`spacing`、`parentheses`。Python、脚本或权限不可用时由模型完整检查并说明未执行原因。

#### 5.1.5 轻量快速路径

**问题**：备忘/Brief 级文档仍需走完整 5 Phase 流程（30+ 检查点），与"快速记录"的定位矛盾。

**机制**：为最轻变体增加一条快速路径，跳过不必要的 Phase。

```
快速路径触发条件：变体 ∈ {Brief, 备忘, PR Note, 决策日志, CI 报告}

Phase 1: 选类型+变体 → 骨架（跳过读者角色定义）
Phase 2: 优先使用已有材料和本地证据，可省事实卡片格式；事实缺口仍按 5.6 路由补齐
Phase 3: 正常编写（启发式仍适用）
Phase 4: 模型完整主检（含 V1-V5）+ 类型专用验证 + 脚本候选裁决；有代码、配置或实际运行结果引用时执行 Step 2；执行 Step 3 叙述重复度，跳过 Step 4
Phase 5: 不另附缺口汇总；正文中的待验证内容和未决事项仍保留
```

**效果**（设计假设，待实测验证）：省去事实卡片包装、读者测试和单独的缺口汇总，不再按固定检查点数量估计节省。必要核验量取决于实际引用的材料。

**不降级的原则不变**：快速路径不跳过真实性要求和必要证据核验，信息源路由与标准路径相同（9 条启发式始终生效）。CI 报告必须依据对应流水线或日志，不从本地源码推断测试结果。

#### 5.1.7 运行时行为

- 仅在手动调用时加载 L0-init；先读共同约束，按实际动作补齐阶段原文，不自动介入无关任务
- 准备选型前读 prepare，确定类型后完整读取对应 L1 模板；核对或获取材料前读 research
- 首次生成文稿、实际骨架文字或建议前读 G1/G3 和 L0-write；实际技术架构决策前读完整 D1，提前输出不豁免
- 初稿后及交付前读 L0-check 与完整 5.3 → 重新核对全部适用规则 → 模型完整主检 → 候选扫描与裁决
- 编写过程中可切换文档类型 → 后续不再采用旧 L1 模板规则（已进入上下文的内容不会自动移除，但新编写和验证以新模板为准）
- 用户可手动请求加载 L2 任意文件
- 快速路径省略事实卡片包装和 Phase 4 Step 4；Step 2 按证据引用情况执行，Step 3 仍执行，外部信息继续遵循 5.6 的隔离路由
- 执行工具不可用时保留完整模型检查并报告限制；规则文件缺失则报告安装不完整，不冒称检查通过

#### 5.1.8 设计文档自身的披露

本设计文档已按渐进式披露原则拆分：

- `design-spec.md`：设计背景、§3 规则与阶段索引、§5 模块摘要及低频委托规则；普通写作不先全文读取
- `runtime/{stage}.md`：准备、取材、编写、验证/交付的完整原文与入口
- `modules/constraints-{common,writing,architecture}.md`：C/G/D 的单源完整规则；其他模块按明确内容条件读取
- 本地设计决策记录：仅供开发追溯，不入库、不随包分发，也不是运行依赖
