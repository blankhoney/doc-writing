# 测试证据呈现指导（按需）

简单 CI 结果按测试报告模板组织，不必通读本文件。新建／行为变更设计读 §5；重试／多配置统计读 §1，验收映射读 §2，跨运行或量化对照读 §3，人工／模型评审、自定义判定器或判定异常读 §4，图表或媒体分别读 §6／§7。只读触发的完整节；状态语义与统计细则在此维护。

## 1. 状态与统计

区分三种计数单位：用例（设计出的检查）、执行项（用例×配置或环境）、尝试（同一执行项的多次运行）。报告开头写明当前统计单位。首次通过、重试后通过与最终结果分别说明，重试原因和次数可见。

unknown、error、N/A 与跳过分开记录，不冒作业务通过或业务失败，也不进入通过率分子；未执行项独立列出。运行结果（是否执行、执行范围、所得结果）、证据可用性（有无可核查记录）与缺陷处置（修复／豁免／遗留）是三个维度，不互相替代。

每个指标各自声明分母与保留规则：跳过、未评分、重试如何计数，不要求所有指标共用一个分母。无可计分样本时写"无可用结果"，不给通过率。

## 2. 需求到证据

按实际关系映射：关键需求／风险 → 场景与条件 → 预期及判定依据 → 结果与证据 → 缺口。一条需求可对应多个场景，也可由多个需求共享一个场景，不强制一一对应，不放任缺口被"基本覆盖"带过。

## 3. 数据与比较

记录版本或提交、环境、数据集与样本量、指标方向与单位、分子分母、基线与目标来源。不同配置、不同运行的数据不得无说明混合汇总：分开给结果，或说明合并口径与影响。

关键失败和少量严重缺陷单独呈现，不被高通过率或均值淹没。

## 4. 判定器

机械断言、人工评审、模型评审与自定义判定器都说明判定依据与适用边界。采用人工／模型评审或自定义判定器时，正常返回也须满足本节：说明判据、样例覆盖与已知误判。判定异常（解析失败、超时、返回不可判）同样触发本节；缺少可靠性资料时说明限制，不自动运行额外评测或引入新工具。

解析失败、缺证据与未执行保留为独立状态，不折算为通过或失败。判定器程序与被引用的标准、阈值本身用正反控制样例核查：既有能通过的样例，也有已知应失败且实际失败的样例。资料缺失时只说明有效性待验证，不断言判定器不能识别坏结果。

## 5. 开发前验证

新建或行为变更设计主动推导验证。先对齐 PRD 列明的风险与验收要求，并从需求本身推导未明说的失败风险，再把每项落实为用例：输入、前置状态、操作、可观察预期、判定依据、环境／数据／证据安排。来源不足时定向查官方或一线方法，记录适用条件与本地化改动，不直接采用其阈值。

- 效果指标明确方向、口径、样本与重复次数、评级区间、边界归属和达标线。
- 评级区间覆盖适用值域且不重叠，边界值归属写明。
- 业务阈值缺失时给有依据的待确认建议并标明未批准，不冒称结论。
- 比较规则固定（同一数据集、判定器与口径），按影响决定复测范围；提前记录停止或升级条件，不自改阈值、不无限评分、不作无变化重复运行。
- 用正反输入确认检查能识别坏结果；Agent QA／Gherkin 的 Then 须有真实断言，按框架的实际失败机制核对，不只看函数返回值。
- 未达标项关联具体缺陷与证据，给出改进建议与影响范围，并按影响复测。

计划、已设计用例、可运行实现与实际运行四者分开记录；尚无代码时可先设计方法与用例，不虚构运行证据。需要系统组织时引用测试计划 C 变体。

## 6. 图表

先给结论、关键阻断和缺口，再给细节。表格用于精确对照与逐项核对；图表只在趋势、分布或构成确有信息量时使用，不设图数配额。

图表与其原始数据、计算同源；数据更新时同步更新图表，核对单位、坐标轴、图例与正文一致，不选择性截断坐标，不用图形掩盖关键失败。

## 7. 媒体与附件

按证明对象选载体：截图证明界面状态，视频证明时序操作，日志证明被记录的那次运行，原始结果文件证明数据。媒体只支撑所记录的对象，不因有日志就宣称全部运行事实已证明。索引标注运行／版本、来源、定位方式与用途；视频给时间点，日志给文件与行号。

含个人信息或敏感内容的媒体先脱敏、确认授权范围再收录；不自动上传媒体，上传与共享需单独授权；访问与保留期遵循项目既有规定。

## 8. 边界

不新增统一数据平台、强制 JSON 结构、自动发布门禁或生产取证中继，不替代目标项目的既有状态定义与工具链；报告只陈述实际执行的规则、已获得的证据和当前批准状态。

沿用目标项目有效状态时给出映射说明；G2 继续负责区分事实、假设、判断与证据性质。编写文档不授权测试执行、付费评测、部署或上传。
